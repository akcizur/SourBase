# WAVE IPTV 1.6.0 · Research implementation

WAVE is a local-first Windows media centre that unifies IPTV, a personal media library, a shared player, EPG, Xtream VOD, local files and authorized RSS/torrent workflows in one Stremio-inspired interface.

## What changed in 1.6.0

- **DPAPI-protected local state:** the entire desktop library snapshot is encrypted with Windows Data Protection API (current-user scope). This includes stream URLs, which may contain provider credentials.
- **Separate secret vault:** Xtream password and the user's private SKTorrent RSS URL are stored separately in a DPAPI-protected file. qBittorrent credentials remain in memory only for the current session.
- **Migration from 1.5.0:** on first launch, a legacy `%AppData%\WAVE IPTV\state.json` is migrated to protected `state.dpapi` and `credentials.dpapi`. The plaintext state file is removed only after the protected files have been written successfully.
- **Desktop browser storage cleanup:** WAVE no longer writes the desktop app state to browser `localStorage`. Legacy local browser state is migrated to the protected local store and removed after the server confirms a successful save.
- **Atomic persistence:** file writes use a temporary file, flush, close and rename sequence to reduce the chance of corrupting the local library after an interrupted write.
- **Compatibility endpoints:** `/api/state` accepts legacy state payloads but extracts any old secret fields before writing; `/api/credentials` is the dedicated protected credential endpoint.

## Main modules

| Area | Purpose |
|---|---|
| Home / Discover | Unified shelves, title cards and global search |
| Library | Saved titles, local videos, favourites and watch history |
| Player | Shared video surface, mini-player, seek and resume state |
| Live TV | M3U/M3U8 channels, groups and XMLTV EPG |
| Movies / Series | Xtream VOD, series seasons and episodes |
| SKTorrent | User-supplied official RSS feed, local catalog and details |
| qBittorrent | Local Web UI connection, download queue and completed-file handoff |
| Local Media | File picker and authenticated loopback byte-range streaming |

## Local operation

1. Run `WAVE IPTV 1.6.0.exe` on Windows 10/11 x64.
2. WAVE binds its local host to `127.0.0.1` only and opens its desktop browser window.
3. Add the user's own M3U/M3U8 playlist, Xtream provider, XMLTV guide, or local media.
4. To use the SKTorrent connector, paste the official RSS URL generated by the user's own account. No tracker login bypass or access-control circumvention is implemented.
5. To manage allowed downloads, run qBittorrent and enable its Web UI on localhost. WAVE passes completed files to its player or an installed VLC/MPV fallback.

The UI, local media, saved library and cached catalog data work offline. Remote IPTV streams, remote EPG, provider catalogs and RSS synchronization need network access to their respective servers.

## Storage and privacy

Desktop data directory:

`%AppData%\WAVE IPTV\`

| File | Description |
|---|---|
| `state.dpapi` | DPAPI-protected application state snapshot, including channel and VOD URLs |
| `credentials.dpapi` | DPAPI-protected Xtream password and SKTorrent RSS URL |
| `app.log` | Local diagnostic log; should not contain passwords or raw credential payloads |

DPAPI uses the current Windows user scope. The protected files are intended to be opened by the same Windows account on the same machine. A different Windows account, a fresh Windows installation, or a damaged user profile may not be able to decrypt them. Export or back up the library from within a future dedicated backup feature before moving Windows profiles.

The qBittorrent username/password are used to establish an in-memory session and are not saved by WAVE. Use qBittorrent Web UI on localhost and do not expose it to the public internet.

## Persistence design note

This release applies the research's main privacy and migration recommendations, but **does not yet implement SQLite**. The current data format is a DPAPI-encrypted JSON snapshot. A future SQLite migration should preserve transactional imports, indexed catalog searches, normalized media metadata and an explicit encrypted-secret boundary. No SQLite dependency was added to this build because the build environment could not retrieve external Go modules; the existing application remains dependency-light and reproducible with the Go standard library.

## Playback notes

- MP4/WebM playback depends on the codecs available in the embedded browser runtime.
- HLS `.m3u8` can use browser-native support where available; otherwise use VLC/MPV.
- MKV and uncommon codecs may require VLC/MPV.
- Torrent playback starts from completed files. Streaming partially downloaded pieces is not implemented.
- Local media streams are served via an authenticated loopback endpoint with HTTP Range support for seeking.

## Build from source

Requires Go 1.23+ and Windows x64 to build the release executable.

```bat
build-windows.bat
```

Manual Windows cross-build (from a host with Go installed):

```powershell
$env:GOOS = "windows"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go test -c -o wave-tests.exe ./...
go build -trimpath -ldflags="-s -w -H=windowsgui" -o "WAVE IPTV 1.6.0.exe" .
```

Tests and static checks:

```bash
go test ./...
go vet ./...
```

The inline browser application script can additionally be syntax-checked with Node.js by extracting the `<script>` block from `web/index.html` and running `node --check` on it.

## Verification boundaries

This source release has Go unit tests, `go vet`, JavaScript syntax validation and a Windows x64 cross-build. A real Windows desktop launch, DPAPI encrypt/decrypt operation on Windows, a real provider account, an actual SKTorrent member feed, and playback against a specific IPTV provider still require physical Windows testing with the user's own accounts and permitted content.
