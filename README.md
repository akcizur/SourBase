# AVMCMP+ · Media Center

AVMCMP+ is a local-first media center for Windows. It brings IPTV, a personal media library, a shared player, EPG, Xtream VOD, local files, an RSS catalogue and an optional local qBittorrent connection into one TV-first interface.

## Interface direction

- **TV-first desktop:** desktop and large displays use a spacious 10-foot layout, larger typography and clear focus states designed for keyboard / remote navigation.
- **Adaptive layouts:** compact tablet navigation and a touch-friendly mobile layout, with responsive media grids and a single source-input hub.
- **One input menu:** add M3U/M3U8 URLs or files, Xtream Codes, XMLTV EPG, local media, RSS catalogues or configure qBittorrent from the main menu.
- **Clean media-center workspace:** Home, Live TV, Movies, Series, Library and Player remain unified rather than opening separate utility windows.

## Included modules

| Area | Purpose |
|---|---|
| Home / Discover | Unified shelves, title cards and global search |
| Library | Saved titles, local videos, favourites and watch history |
| Player | Shared video surface, mini-player, seek and resume state |
| Live TV | M3U / M3U8 channels, groups and XMLTV EPG |
| Movies / Series | Xtream VOD, seasons and episodes |
| RSS catalogue | User-supplied RSS feed, local import and item details |
| qBittorrent | Local Web UI connection, download queue and completed-file handoff |
| Local Media | File picker and authenticated loopback byte-range streaming |

## Local operation

1. Build and run `AVMCMP+.exe` on Windows 10/11 x64, or download it from the GitHub Actions build artifact.
2. AVMCMP+ binds its local host to `127.0.0.1` only and opens its embedded browser window.
3. Open **Přidat vstup** in the main menu to add your own M3U/M3U8 playlist, Xtream provider, XMLTV guide, local media or RSS source.
4. To use the RSS connector, paste the official feed URL generated by your own account. No tracker login bypass or access-control circumvention is implemented.
5. To manage permitted downloads, run qBittorrent and enable its Web UI on localhost. AVMCMP+ passes completed files to its player or an installed VLC/MPV fallback.

The interface, local media, saved library and cached catalogue data work offline. Remote streams, remote EPG, provider catalogues and RSS synchronization require network access to their respective servers.

## Storage and privacy

The desktop data directory remains:

`%AppData%\WAVE IPTV\`

The folder name is intentionally retained for compatibility with existing WAVE IPTV installations and their encrypted data.

| File | Description |
|---|---|
| `state.dpapi` | DPAPI-protected application state snapshot, including channel and VOD URLs |
| `credentials.dpapi` | DPAPI-protected Xtream password and private RSS URL |
| `app.log` | Local diagnostic log; should not contain passwords or raw credential payloads |

DPAPI uses the current Windows user scope. Protected files are intended to be opened by the same Windows account on the same machine. A different account, a fresh Windows installation or a damaged user profile may not be able to decrypt them. qBittorrent credentials are session-only and remain in memory while the application is running. Keep qBittorrent Web UI on localhost; do not expose it to the public internet.

## Playback notes

- MP4/WebM playback depends on codecs available in the embedded browser runtime.
- HLS `.m3u8` can use browser-native support where available; otherwise use VLC/MPV.
- MKV and uncommon codecs may require VLC/MPV.
- Torrent playback starts from completed files. Streaming partially downloaded pieces is not implemented.
- Local media streams use an authenticated loopback endpoint with HTTP Range support for seeking.

## Build from source

Requires Go 1.23+ and Windows x64.

```bat
build-windows.bat
```

Manual Windows cross-build:

```powershell
$env:GOOS = "windows"
$env:GOARCH = "amd64"
$env:CGO_ENABLED = "0"
go test ./...
go vet ./...
go build -trimpath -ldflags="-s -w -H=windowsgui" -o "AVMCMP+.exe" .
```

Tests and static checks:

```bash
go test ./...
go vet ./...
```

The embedded browser script can be syntax-checked by extracting the inline `<script>` block from `web/index.html` and running `node --check` on it.

## Verification boundaries

The Go test suite and static analysis cover the local server, protected state, migrations, media range handling and qBittorrent integration. A real Windows desktop launch, DPAPI round-trip on Windows, real provider accounts and playback against a specific IPTV provider still require testing on Windows with the user's own accounts and permitted content.
